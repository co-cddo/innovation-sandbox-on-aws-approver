## What Went Well

### 1. Smart Architecture Discovery (Story 7.2.3)
The team discovered that AWS Chatbot custom actions can be CDK-managed using `AWS::Chatbot::CfnCustomAction`. This was a significant improvement over the original plan of manual AWS Console configuration.

**Impact:**
- Infrastructure as Code - configuration is version controlled
- Repeatable deployments across environments
- No manual console steps required

### 2. Appropriate Story Dropping (Story 7.2.4)
Story 7.2.4 "Implement Idempotency for Action Lambdas" was dropped after discovering the ISB Lambda already handles idempotency via 409 Conflict responses. The `isAlreadyProcessedResult()` function at `slack-action-base.ts:212-221` was sufficient.

**Impact:**
- Avoided unnecessary complexity
- Leveraged existing patterns
- Reduced implementation scope

### 3. Comprehensive Documentation
Stories 7.5.1, 7.5.2, and 7.5.3 delivered thorough operational documentation:
- Approver Access Management Guide - channel-based access control
- Operator Onboarding Canvas - all 19 scoring rules explained
- Custom Action Configuration Runbook - CDK-managed deployment docs

### 4. Observability from Day One
Stories 7.4.1 and 7.4.2 established comprehensive monitoring:
- Structured CloudWatch logging with correlation IDs
- Error rate alarms for both Slack action Lambdas
- SNS delivery failure alarm
- Incident response runbook with CloudWatch Insights queries

### 5. Clean Legacy Code Removal (Story 7.5.4)
The migration from webhooks to SNS was clean:
- Removed ~390 lines of legacy code
- Deleted 5 files (POC stack, webhook service, secrets retrieval, tests)
- SNS is now the sole notification mechanism
- 30-minute fallback preserved

## Challenges and Lessons Learned

### 1. Line Number Drift in Documentation
**Challenge:** After Story 7.5.4 removed webhook code (~170 lines), line number references in Story 7.5.5 became stale.

**Root Cause:** Stories referenced specific line numbers that shift when code changes.

**Lesson:** Use file-based references (e.g., "look for `handleScheduledQueueCheck` function") rather than line numbers in story documentation.

### 2. Test Command Syntax Inconsistency
**Challenge:** Story documentation used `--grep` for test filtering, but Vitest uses `-t`.

**Root Cause:** Jest/Vitest syntax differences not documented in project standards.

**Lesson:** Document tool-specific syntax in CLAUDE.md to prevent recurring errors.

### 3. Manual Validation Skipped
**Challenge:** Story 7.5.4 AC1 (manual validation of 3+ approve/deny actions) was skipped by user request.

**Risk:** Could have missed edge cases without explicit production verification.

**Lesson:** Manual validation steps should be documented as "verified by deployment" or explicitly waived with rationale.

### 4. Pre-existing Technical Debt
**Challenge:** TypeScript errors in approver-stack.ts and slack-action-base.ts pre-date Epic 7.

**Impact:** CDK deprecation warnings and type errors appear in builds but don't affect functionality.

**Lesson:** Technical debt should be tracked separately and addressed in dedicated cleanup sprints.
