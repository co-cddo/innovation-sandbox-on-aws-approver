## What Went Well

### 1. Business Hours Detection (Story 4.1)
- Clean implementation using JavaScript's native `Intl` API for timezone-safe date handling
- Automatic BST/GMT transition handling via `Europe/London` timezone
- UK bank holidays fetched from gov.uk ICS endpoint with 24-hour caching
- 30 new tests covering all timezone edge cases
- End-of-window bonus (5-7pm London) cleanly integrated into scoring engine

### 2. Delayed Processing (Story 4.2)
- Robust event routing for three trigger types: LeaseRequested, scheduled.queue-check, AccountCleanupSucceeded
- FIFO ordering implemented via `SentTimestamp` sorting
- SQS service extended with `receiveMessages()`, `deleteMessage()`, `getQueueDepth()` methods
- DynamoDB service extended with `getAvailableAccountsCount()` for account availability
- Pessimistic fallback on query failure (assume no accounts available)
- Queue depth logging before and after processing

### 3. Rate Limiting (Story 4.3)
- Soft scoring penalties rather than hard blocks - intelligent escalation approach
- Extended scoring engine from 16 to 18 rules seamlessly
- Reused existing user/org lease history data - no new DynamoDB changes needed
- Clear separation: user limit (+5 per extra beyond 2/hour), org limit (+3 flat for 5+ users/hour)
- 15 new tests covering all rate limit scenarios

### 4. Queue Expiry (Story 4.4)
- Business day calculation correctly excludes weekends AND UK bank holidays
- `countBusinessDays()` and `isQueueExpired()` cleanly integrate with existing business-hours module
- LeaseDenied event type added for queue timeout scenario
- Reference number generation (ISB-YYYY-NNNN format) implemented
- Code review caught and fixed unused function (isSameDay) with timezone inconsistency

## Challenges Encountered

### 1. Test Date Staleness
**Issue:** Existing handler tests used hardcoded dates from 2024 (`receivedAt: '2024-01-01T09:00:00Z'`)
**Impact:** New expiry logic detected these as expired (>1 year old)
**Resolution:** Changed to dynamic dates using `new Date()` calculations
**Lesson:** Use dynamic/relative dates in tests to prevent time-based test failures

### 2. Mock Service Completeness
**Issue:** Mock EventBridge service missing `emitLeaseDenied` method after adding it
**Impact:** Tests failed with TypeScript compilation errors
**Resolution:** Added `emitLeaseDenied` to mock at handler.test.ts line 101
**Lesson:** When adding new methods to interfaces, immediately update all mock implementations

### 3. Unused Function with Timezone Bug
**Issue:** `isSameDay()` function was created but never used, and used UTC instead of London timezone
**Resolution:** Removed function and its 2 tests entirely during code review
**Lesson:** Avoid speculative code - only implement what's actually needed

## Key Insights

1. **Building on Solid Foundation** - Epic 3's business hours infrastructure (bank holidays service, timezone utilities) made Epic 4 implementation straightforward. The factory pattern for services enabled clean testing.

2. **Soft Limits > Hard Blocks** - Rate limiting as scoring penalties rather than hard rejections provides intelligent escalation while still allowing urgent requests through with operator review.

3. **Pessimistic Fallback Consistency** - Same pattern used across Epic 3 (DynamoDB, S3, Bedrock) applied naturally to Epic 4 (account availability, queue processing). Fail-closed behavior is now a project standard.

4. **Code Review Value** - Three issues caught in code review (M1, L1, S2, L4) that would have been tech debt or potential bugs.
