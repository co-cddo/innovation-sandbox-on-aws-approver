## Challenges Encountered

### 1. Bedrock Cross-Region Inference
**Issue:** Initial deployment failed with Bedrock permission errors
**Resolution:** Added all US regions (us-west-2, us-east-1, us-east-2, us-west-1) to IAM policy
**Lesson:** Cross-region inference profiles require permissions in all routing regions

### 2. KMS Encryption
**Issue:** DynamoDB queries failed with KMS decrypt errors
**Resolution:** Added KMS decrypt permission for ISB table encryption key
**Lesson:** When accessing cross-account/cross-stack DynamoDB tables, check KMS requirements

### 3. Environment Variable Mismatch
**Issue:** Lambda couldn't find S3 bucket for domain verification
**Resolution:** CDK used `domainListBucketName` but code expected `DOMAIN_ALLOWLIST_BUCKET`
**Lesson:** Maintain strict naming conventions between CDK and runtime code

### 4. Hardcoded Configuration
**Issue:** ISB integration values scattered across multiple files
**Resolution:** Code review centralized all values in `environments.ts`
**Lesson:** Single-source-of-truth for configuration prevents drift

---

## Key Insights

1. **Pessimistic Fallback Pattern** - All external dependencies (DynamoDB, S3, Bedrock) use pessimistic fallback on errors. This ensures fail-closed behavior without crashing.

2. **Circuit Breaker Value** - The circuit breaker for Bedrock prevents cascade failures and allows graceful degradation to rule-based fallback.

3. **Infrastructure as Code** - Deploying domain list via CDK BucketDeployment is more reliable than manual S3 uploads.

4. **Code Review Discipline** - Three-pass code review caught hardcoded values that would have been tech debt.
