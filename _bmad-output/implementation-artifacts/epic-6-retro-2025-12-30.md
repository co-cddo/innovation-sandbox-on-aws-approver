## What Went Well

### 1. Pure Function Design
The cooldown logic was implemented as pure functions with injected timestamps, making unit testing extremely reliable. No flaky tests related to timing.

### 2. TOCTOU Race Condition Handling
Successfully identified and implemented handling for the Time-Of-Check-Time-Of-Use race condition where an account could become unavailable between the cooldown check and the approval attempt. The re-queue mechanism with 5-minute delay ensures no requests are lost.

### 3. Capacity Crunch Detection
Implemented smart capacity detection that distinguishes between:
- Normal cooldown (some accounts cooling, will be ready soon)
- Capacity crunch (all accounts active, needs operator attention)

Alert throttling (1 per hour) prevents Slack spam during extended high-demand periods.

### 4. Queue Position Estimation
The queue estimation algorithm provides realistic wait times:
- Based on soonest cooling account
- Factors in queue position (4hr per position)
- User-friendly messaging without technical jargon

### 5. Test Coverage
All stories achieved comprehensive test coverage with edge cases for:
- 24hr cooldown boundary (23h59m vs 24h00m)
- 60-minute grace period for new accounts
- BST/GMT timezone boundary
- Race condition recovery

## Challenges Encountered

### 1. ISB Lambda API Path Discovery
**Challenge:** Initial implementation used `/api/accounts` but the actual ISB endpoint was `/accounts`.
**Resolution:** Corrected the endpoint path after E2E testing revealed the issue.

### 2. Session Continuation
**Challenge:** Complex work spanning multiple conversation sessions required careful state preservation.
**Resolution:** Story files served as effective handoff documentation with clear task checkboxes.

### 3. Mock Object Consistency
**Challenge:** Adding `notifyCapacityCrunch()` to SlackService required updating all mock objects in test files.
**Resolution:** Updated all three mock instances in handler.test.ts.

---

## Key Insights

1. **Pure Functions + Dependency Injection = Testable Code**
   The pattern of injecting `nowTimestamp` instead of using `new Date()` directly made tests deterministic.

2. **Document-Driven Development**
   Story markdown files with detailed Dev Notes sections enabled seamless handoffs between sessions.

3. **Defensive Programming for Race Conditions**
   The TOCTOU handling pattern should be applied to other similar async operations where state can change between check and action.

4. **User-Friendly Messaging**
   Avoiding technical terms like "cooldown" in user messages ("routine maintenance" instead) improves UX.
